REST API Application Factory Reference#

This reference describes create_app and load_config for developers constructing REST API applications. It covers their parameters, return values, validation, input precedence and supported overrides. Shared environment defaults and key-file constraints are listed in REST API Configuration Reference; command usage is listed in dioptra-api Command Reference.

create_app#

create_app(env: str | None = None, injector: injector.Injector | None = None, *, settings: dioptra.restapi.config.BaseConfig | None = None, overrides: collections.abc.Mapping[str, object] | None = None) → flask.app.Flask[source]#

Construct an API application after validating its settings.

Supply a mode and optional overrides, or supply a previously resolved settings instance. The settings belong to this application and must not be mutated. They contain the signing key, so do not print or serialize them. Invalid or conflicting settings fail before extensions or default clients initialize. A supplied settings instance is validated; if the mode environment variable is present, it is ignored with a warning.

Parameters

  • env – dev or prod. When resolving settings, omission selects DIOPTRA_RESTAPI_ENV. Do not supply this with settings.

  • injector – Injector used by RESTX views. If omitted, construct one with the default services. A supplied injector does not alter policy.

  • settings – A configuration returned by load_config. Do not combine it with env or overrides.

  • overrides – Typed values for settings accepted by load_config. They precede named environment inputs and defaults. Do not supply these with settings.

Returns

An initialized and configured Flask application.

Raises

ValueError – If settings inputs conflict or configuration validation fails.

Input Forms#

Call form

Behavior

settings=None

Resolve configuration using env, overrides and the current environment.

Resolved settings with env=None and overrides=None.

Validate that instance without ambient configuration resolution.

Resolved settings with any non-None env or overrides.

Raise ValueError. An empty overrides mapping also conflicts.

With supplied settings, a present DIOPTRA_RESTAPI_ENV is ignored and produces a warning. Supplied settings are an alternative input form, not another precedence level.

Mode Precedence#

When create_app resolves configuration (settings=None), it selects the mode from these sources, in descending priority. The same rule applies to load_config.

Priority

Source

When selected

1

env argument.

The argument is not None.

2

DIOPTRA_RESTAPI_ENV.

env is omitted or None.

There is no default mode. The selected value must be dev or prod; missing, empty or unsupported values raise ValueError. An invalid explicit argument does not fall back to the environment variable. For example, env="" fails even when DIOPTRA_RESTAPI_ENV=prod. Platform restrictions are listed in REST API Configuration Reference.

load_config#

load_config(env: str | None = None, *, overrides: collections.abc.Mapping[str, object] | None = None) → dioptra.restapi.config.BaseConfig[source]#

Resolve a fresh API configuration from one environment snapshot.

Explicit typed overrides precede named environment inputs and class defaults. The protected key file must already exist; resolution never creates or repairs it. The returned instance belongs to one application and must not be mutated. It contains the signing key, so do not print or serialize it. Later environment changes affect future resolution, not applications using this instance. DIOPTRA_MAX_PAGE_SIZE applies to paginated endpoints and must be at least 10. Session protection accepts basic, strong or None; the environment string none selects None.

Parameters

  • env – dev or prod. If omitted, select DIOPTRA_RESTAPI_ENV.

  • overrides – Mapping of schema setting names to typed values, plus the optional SECRET_KEY_FILE path. Unsupported names are rejected. See the schema and class defaults for the accepted settings.

Returns

A validated development or production configuration, including the key read from the selected file and the resolved database and service URIs.

Raises

ValueError – If mode, settings, retired environment inputs, or the selected key file fail validation. Diagnostics do not include credential values.

Typed Overrides#

For each setting, resolution uses these sources in descending priority.

  1. The typed value in overrides.

  2. Its named environment variable, when supported.

  3. The packaged default.

An invalid selected value is rejected without falling back. Override keys use the resolved attribute names below. Environment defaults and value constraints are defined in Environment Variables.
